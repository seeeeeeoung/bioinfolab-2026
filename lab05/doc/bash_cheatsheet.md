# 나의 bash 치트시트 (03~05)

## 스크립트 만드는 다섯 단계
1. 터미널에서 명령어를 한 줄씩 직접 실행 → 명령어 자체가 되는지 확인
2. 그대로 파일에 옮기고 `bash src/이름.sh` → 파일로도 똑같은지
3. 바뀔 값을 변수로 → `FILE="data/seqs.fasta"`
4. 변수를 인자로 → `FILE="$1"`
5. 검사 추가 → 인자 없으면 사용법, 파일 없으면 오류, 둘 다 `exit 1`
- 단계를 건너뛰지 말 것. 앞 단계가 되면 문제는 그다음 단계에 있다.

## 내가 실제로 한 실수
- **`=` 양쪽 공백**: `DIR = $1` → `DIR: command not found`. 바르게는 `DIR="$1"`
- **따옴표 빠뜨림**: `mkdir -p $NAME/data`에 "my project"를 주니 `my`, `project`가 따로 생김 → 항상 `"$NAME"`
- **`done` 빠뜨림**: `unexpected end of file`. 문법 오류는 `set -x`로도 안 보임
- **편집 창과 터미널 헷갈림**: 스크립트에 `bash`가 섞여 `data/seqs.fastabash` 오류 → 스크립트 내용은 편집 창, 실행은 터미널
- **붙여넣을 때 마지막 줄 잘림** → 저장 후 `cat src/파일.sh`로 확인
- **템플릿 없이 저장소 생성** → `cd` 후 `/home/codespace`. 파일 목록에 `lab-template`이 있는지 확인

## 고장 났을 때
- 오류는 **마지막 줄부터**, 파일 / 몇 번째 줄 / 무엇에 대해 / 어떤 문제로 나눠 읽기
- `echo $?` → 0이면 성공, 아니면 실패. 출력이 없다고 성공이 아님 (`grep`이 못 찾으면 1)
- 파이프의 종료 상태는 **마지막 명령어** 것: `ls nowhere | wc -l` → 0
- 두 번째 줄에 `set -x` → `+` 줄로 실제 실행 확인. 다 고치면 지우기

## 따옴표
- `"$B"` → 값으로 바뀜 (기본으로 이것) / `'$B'` → 글자 그대로 `$B`
- 빈 변수 + 따옴표 없음 = 위험: `$OUT/result.txt` → `/result.txt`
- 와일드카드는 따옴표 밖: `"$DIR"/*.fasta`

## 검사식 (대괄호 안쪽 공백 필수!)
- `[ -z "$1" ]` 인자 없음 / `[ ! -f "$1" ]` 파일 없음 / `[ -d "$1" ]` 폴더 있음
- `[ "$A" -lt 13 ]` 숫자 비교 (정수만!) / `||` 또는 / `!` 뒤집기
- `$0` 스크립트 이름, `exit 1` 실패로 끝내기

## 자주 쓸 명령어
- 서열 개수: `grep -c ">" 파일` / 헤더 빼기: `grep -v ">" 파일`
- 이름만: `grep ">" 파일 | cut -d " " -f 1 | tr -d ">"`
- 총 염기 수: `grep -v ">" 파일 | tr -d "\n" | wc -c`
- 파일 이름만: `basename "$F"` / 탭 출력: `echo -e "a\tb"`
- 한 줄씩 읽기: `while read LINE; do echo "${#LINE}"; done < 파일`
- 결과 저장: `./src/batchinfo.sh data > result.tsv`
